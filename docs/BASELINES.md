# Baselines

Tool-level scores of the two baselines from PLAN.md §7.4 and of CSyk itself, recorded with
`npm run eval -- --adapter <b0|b1|csyk>`. Tokens are o200k_base counts of what the agent reads.

- **B0:** built-in tools only: ripgrep, then a whole-file read of the first match.
- **B1:** CodeSift over MCP, as its own rules direct (`search_symbols` with source,
  `find_references`, `search_text`).
- **CSyk:** `find` for A and B, `refs` for C, `grep` for E.

Cases are generated by `eval/generate.ts` from each language's own server (`tsc --lsp`, pyright,
gopls, the Dart analysis server), 30 per category, seed 1, leaving out tests, generated code,
function locals and names that are only imported. A cases expect every top-level or member
declaration of a name, as the whole range the server's outline gives it, never an import path or a
same-named local. A B query must be answered by exactly one name in the repo (same letters, or
each query word starting a name word in order): a query that fits several names equally is
ambiguous, not fuzzy. Recorded 2026-10-28.

## Checking C against the servers' own search

CSyk's references and the oracle share a method (each written mention, resolved by the server), so
their agreement alone proves little. On every public corpus CSyk was also compared, case by case,
with `textDocument/references`, a different algorithm:

| corpus | server | same lines | CSyk misses |
|---|---|---|---|
| excalidraw | `tsc --lsp` | 6 / 30 | 1 case: a default import under another name |
| dispatch | pyright | 29 / 30 | 1 case: a name listed as a string in `__all__` |
| pocketbase | gopls | 30 / 30 | none |
| wonderous | Dart analysis server | 30 / 30 | none |

On excalidraw, CSyk's only extra lines are `import { … }` and `export { … } from` specifiers,
which `tsc` leaves out and the cases count. What CSyk misses is the limit the method states: a
name written under another name (`import Content from`, `import { a as b }`) or inside a string is
not followed.

## What the numbers say

- Grep finds every reference but a quarter to a third of what it returns is noise: comments,
  strings, import paths and same-named symbols elsewhere. CodeSift's `find_references` is text
  based and scores the same. Resolving each mention through the language server removes all of
  it, in all four languages.
- Grep cannot rank, so an exact-name search often opens an importing file first; it cannot match
  a fuzzy name at all. CSyk ranks the declaration first every time but once.
- Token layer: across A, B, C and E together CSyk reads 97–99% fewer tokens than B0 on every
  corpus, and under half as many in every single category (C on wonderous is the closest: 82
  against 169), at the same or a higher pass rate. Where CodeSift finds the symbol at all, CSyk's
  A and B answers cost a sixth to a twentieth of its: one line per symbol, no source until `read`
  asks for it. CodeSift's
  single bare line still beats CSyk's on E, where CSyk also names the enclosing symbol, which is
  the answer E asks for.
- Tool-level tokens are not agent-level tokens: the headless agent benchmark (P6) measures those.
- CSyk reaches these scores with name matching alone (exact, squashed, prefix, substring, word
  prefix). BM25F over signatures and bodies waits for concept questions (F), where names alone
  fall short.
